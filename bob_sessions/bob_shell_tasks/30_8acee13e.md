### Bob · 0.0432 Bobcoins

All 17 tests pass. The bug was in [`format_approx_duration()`](hc/lib/date.py:72): the guard condition was `days != 1` instead of `days == 1`, which caused it to:

- Always enter the first branch (for any non-zero day count, including 3 days), returning the hardcoded string `"1 day {hours} h"`
- Never reach the `if days:` branch at all for multi-day durations
- For zero-day inputs, skip both branches and fall through to the `if hours:` check — returning `"1 day …"` even for pure-hours or pure-minutes inputs

The fix: `days != 1` → `days == 1`.

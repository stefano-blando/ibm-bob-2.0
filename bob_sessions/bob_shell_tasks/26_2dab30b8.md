### [`app/auth/limiter.py`](app/auth/limiter.py) — new file

A self-contained, thread-safe sliding-window rate limiter backed by an in-process `dict[str, deque]` (no Redis required):

| Symbol | Purpose |
|---|---|
| `is_rate_limited(ip)` | Returns `True` if the IP has ≥ 5 failures in the last 60 s |
| `record_failed_attempt(ip)` | Appends the current timestamp to that IP's failure deque |

`_prune()` evicts timestamps older than 60 s before every check, so the window truly slides.

---

### [`app/auth/routes.py`](app/auth/routes.py) — two small additions to `login()`

1. **Before** form processing on every `POST`, call `is_rate_limited(ip)` → `abort(429)` if the IP is blocked.  
2. **Only on a failed credential check**, call `record_failed_attempt(ip)`. Successful logins and GET requests are never counted.

```
POST /auth/login  (wrong password, attempt 1–4)  →  flash + redirect (normal)
POST /auth/login  (wrong password, attempt 5)    →  flash + redirect (normal, but now blocked)
POST /auth/login  (attempt 6 within 60 s)        →  HTTP 429
```

Once the 60-second window has passed (oldest failure slides out), attempts are allowed again automatically.

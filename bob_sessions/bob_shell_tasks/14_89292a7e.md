### Bob · 0.0431 Bobcoins

The root cause is immediately clear. In [`get_post()`](flaskr/blog.py:54), the authorization check logic is **inverted**:

```python
if check_author and post["author_id"] == g.user["id"]:
    abort(403)
```

It aborts with 403 when the current user **IS** the author, but it should abort when the current user is **NOT** the author. The `==` should be `!=`.

This explains all four failures:
- `test_author_required`: user 1 owns post 1, but after changing it to user 2, user 1 gets 400 (no 403) when they should get 403
- `test_update`: user 1 gets 403 accessing their own post 1 — they shouldn't
- `test_create_update_validate[/1/update]`: same — user 1 can't access their own post
- `test_delete`: same — user 1 can't delete their own post

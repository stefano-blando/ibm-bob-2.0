### [`flaskr/markdown.py`](flaskr/markdown.py) *(new file)*
A dedicated module that builds a single `MarkdownIt` instance with the `html_block` and `html_inline` rules disabled. Disabling those two rules causes `markdown-it-py` to escape any raw HTML tags the author types (e.g. `<script>` becomes `&lt;script&gt;`), while still processing all Markdown syntax (bold, italics, links, lists). The rendered string is wrapped in `markupsafe.Markup` so Jinja2 doesn't double-escape it.

### [`flaskr/__init__.py`](flaskr/__init__.py)
Registers `render_markdown` as the `"markdown"` Jinja2 filter on the app so templates can call it.

### [`flaskr/templates/blog/index.html`](flaskr/templates/blog/index.html)
Changed the body output from:
```html
<p class="body">{{ post['body'] }}</p>
```
to:
```html
<div class="body">{{ post['body'] | markdown }}</div>
```
A `<div>` is used instead of `<p>` because the Markdown renderer emits block-level elements (like `<ul>`, `<p>`) that cannot be nested inside a `<p>`. The `| markdown` filter already returns a `Markup` object, so Jinja2 outputs it as safe HTML without the `| safe` filter needed.

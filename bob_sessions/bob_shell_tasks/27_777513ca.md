### Changes made

#### New file: [`app/auth/rate_limit.py`](app/auth/rate_limit.py)

A small, self-contained module with three public functions:

| Function | Purpose |
|---|---|
| `is_rate_limited(ip)` | Returns `True` if ≥5 failures recorded within the last 60 s |
| `record_failed_attempt(ip)` | Appends a timestamp for one failure |
| `clear_attempts(ip)` | Resets the counter on successful login |

**Storage strategy (dual back-end):**
- **Primary — Redis** (`current_app.redis`): timestamps are stored as a list with a 60 s TTL. Works across multiple worker processes.
- **Fallback — in-process dict** (thread-safe with `threading.Lock`): used automatically whenever Redis raises any exception (no Redis running, connection refused, etc.). This is what the test environment uses.

#### Modified: [`app/auth/routes.py`](app/auth/routes.py)

Three targeted additions to [`login()`](app/auth/routes.py:17):

1. **Before processing the form** — if it's a `POST` from a rate-limited IP, `abort(429)` immediately.
2. **On authentication failure** — call `record_failed_attempt(ip)` to count the bad try.
3. **On successful login** — call `clear_attempts(ip)` so a legitimate user isn't locked out.

The rate-limit check intentionally fires **before** form validation so that a locked-out attacker can't bypass the counter by submitting a structurally invalid form.

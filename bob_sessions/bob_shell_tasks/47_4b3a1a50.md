### What changed

**[`app/auth/routes.py`](app/auth/routes.py)**

Three additions at the top of the file, before the `login` view:

| Symbol | Purpose |
|---|---|
| `_RATE_LIMIT_ATTEMPTS = 5` | Maximum allowed failures before blocking |
| `_RATE_LIMIT_WINDOW = 60` | Sliding window size in seconds |
| `_failed_attempts: dict` | Module-level registry: `IP → deque[timestamp]` |
| [`_is_rate_limited(ip)`](app/auth/routes.py:22) | Returns `True` when the IP has ≥ 5 failures in the last 60 s; evicts stale timestamps on every call |
| [`_record_failure(ip)`](app/auth/routes.py:33) | Appends the current timestamp to the IP's deque; evicts stale timestamps first |

The [`login()`](app/auth/routes.py:43) view now:

1. **Checks the limit on entry** (both GET and POST) — blocked IPs get `abort(429)` immediately.
2. **Records a failure** whenever credentials are wrong, then **re-checks** — so the 5th bad attempt itself is also rejected with 429 rather than receiving the flash message.
3. A **successful login is never recorded** as a failure, so it neither blocks the user nor resets the counter (deliberate: a single correct login can't unblock a brute-force IP).

The implementation uses only stdlib (`time`, `collections.deque`) — no new dependencies. The in-memory store is per-process; it resets on restart, which is consistent with the stated requirement.

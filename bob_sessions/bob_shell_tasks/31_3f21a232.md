### Bob · 0.0507 Bobcoins

All cases pass. The fix is a one-character change in [`hc/lib/date.py`](hc/lib/date.py:72).

**Root cause:** In [`format_approx_duration()`](hc/lib/date.py:65), line 72 had `days != 1` instead of `days == 1`. This inverted the singular/plural logic — any time `days` was *not* 1 (e.g. 3 days), it would incorrectly return `"1 day …"`, and only when `days == 1` would it fall through to the next branch (which returned `"3 days …"` for 1 day). The fix simply changes `!=` to `==`.

The bug is on line 54 of [`flaskr/blog.py`](flaskr/blog.py:54). The condition is inverted:

```python
if check_author and post["author_id"] == g.user["id"]:
    abort(403)
```

This aborts with 403 when the user **is** the author — the exact opposite of the intended behaviour. It should abort when the user is **not** the author (`!=`).

This explains all four failures:
- `test_update` and `test_create_update_validate[/1/update]` and `test_delete`: the logged-in user (id=1) owns post 1, so `== g.user["id"]` is `True` → erroneously gets 403.
- `test_author_required`: post 1's author is changed to user 2, so `== g.user["id"]` (user 1) is `False` → no abort → returns 400 (missing form data) instead of 403.
